# VoidOCR → Meta Core · local integration 0.1 candidate

## Что подключено

Авторский runtime из Lacinnik/architectonica-az-buki, commit
7fc57decef0467cfb37a6595856b0333d9582510, перенесён целиком по графу импортов.
Все девять файлов vendor сохранены побайтово; SHA-256 перечислены в provenance.json.
Лицензия MIT сохранена. Пороговые таблицы и порядок NEG → GOV → META → DEMONS
не переписаны. Защитная проверка находится вне vendor, в runtime.mjs.
Новая интеграция — candidate, а не признание исходной модели научно подтверждённой.

## Контракт передачи

- Источник: сохранённый VoidOCR trace 1.1.0, решение ALLOW и устойчивость 2–3.
- Получатель: только meta-core-v2. Назначение: evaluate-local-draft.
- Объект переносится дословно; плита берётся из исходного quadrant.
- Текст не передаётся в query/hash или внешние API.
- Передача хранится в sessionStorage; получатель сверяет её с localStorage-источником.
- 30 минут от исходной записи, а не от повторной отправки. Это технический TTL, не канон.
- Чужая схема/получатель, DENY, несоответствие журналу, будущее время,
  истечение срока, уже закрытый id и повреждённое хранилище блокируют приём.
- После предварительной проверки пользователь отдельно фиксирует квитанцию.
  Квитанция и отметка закрытия записываются одним значением localStorage;
  запись перечитывается. При ошибке подтверждённое сохранение не показывается.
- Журнал не обрезается молча; при 500 квитанциях новая запись останавливается.
  После перезагрузки последние 10 квитанций доступны для повторного экспорта.

## Проверка получателя

Исходный ALLOW не даёт принимающему контуру автоматического разрешения.
Требуются явный риск без стопа, известный контекст, владелец и подтверждение
получателя, локальное обратимое воздействие, фаза, действие и инвариант.
Для организации нужна отдельно заявленная ответственная сторона.
Публичный контекст, внешнее совместное и необратимое воздействие закрыты.
Неизвестные фазы/плиты не могут попасть под разрешающие значения по умолчанию.

Метрики вводятся явно в диапазоне 0–1 с основаниями. Пустота не превращается
в ноль. Q из VoidOCR равен null и не вычисляется из устойчивости.
Для прохождения ворот требуется отдельно сообщённый бинарный возврат 0/1
с описанием наблюдения по тому же объекту. Он маркируется user-reported,
не independently-verified. Пороги исходного runtime применяются к нему без изменения.

PASS_INTERNAL — прохождение внутренней технической проверки.
HOLD_PROTOCOL — проверка не пройдена. Ни один результат не исполняет действия.
Экспорт содержит входные данные, основания, пройденные проверки и исходный ответ runtime.
Оценка runtime не является доверенным удостоверением.

## Ограничения

Браузерное хранилище не подписано и доступно владельцу браузера и коду того же origin.
Сверка с журналом не устанавливает личность, полномочия или подлинность.
Локальная блокировка повторного id не является распределённой транзакцией:
одновременные записи разных вкладок не имеют серверной блокировки.
Для реального исполнения, межпользовательского обмена, отзыва полномочий,
межустройственного переноса и строгой защиты от повторов нужен отдельный
аутентифицированный серверный контракт; он здесь не реализован.
Часы берутся с устройства; источник может быть вытеснен из журнала VoidOCR,
и тогда приём закрывается. Новая передача заменяет одну ожидающую в этой вкладке.
Смысл порогов и эмпирическая эффективность этим выпуском не валидируются.
