## Фактическое поведение опубликованного сайта

Проверен настоящий GitHub Pages в WebKit 26.5 с профилем iPhone 13 (390 × 664 CSS-пикселя). Через страницу платформы установлен настоящий worker, затем открыта SC-5. Созданы только синтетические записи в изолированном браузерном контексте.

Сеть отключалась разрывом TCP-соединений тестового прокси и отказом в новых соединениях. Флаг `context.setOffline` в этом измерении **не применялся**. Это проверка потери сетевой связи, а не физического авиарежима iPhone; `navigator.onLine` мог оставаться true.

| Сценарий опубликованного релиза | Результат |
| --- | --- |
| SC-5 онлайн: 15 индикаторов, интерактивная форма | Работает; горизонтальное переполнение 0 px |
| Предварительный кэш после активации worker | Записей SC-5 нет |
| Сохранение новой оценки в уже загруженной форме после разрыва сети | Работает; журнал вырос с одной записи до двух |
| Новая вкладка SC-5 с новым `cycleId` / `phase` без сети | Не запускается; ответ worker — ошибка |
| Перезагрузка уже посещённой SC-5 без сети | Не запускается |
| Восстановление сети и повторное открытие | Обе записи доступны; строка localStorage совпала побайтно |

Причина подтверждена исходником и браузером: HTML SC-5 не входит в SHELL, успешные HTML-навигации не записываются в программный кэш, fallback для SC-5 отсутствует. Посещение лаборатории может прогреть кэш модулей, но не обеспечивает повторную загрузку HTML.

## Подготовленное исправление

Единственный изменённый исполняемый файл продукта — `public-web/public/sw.js`:

1. Ревизия кэша повышена до `sc5-offline-20261112-r1`.
2. В атомарный `cache.addAll(SHELL)` добавлены каталог SC-5, `index.html`, `sc5-core.mjs` и `temporal-replay.mjs`. Это полный граф модулей, который реально загружает страница; CSS встроен в HTML.
3. Добавлен navigation fallback для `/labs/sc5-chronos/` и `/labs/sc5-chronos/index.html`, включая query-параметры. Параметры остаются в URL страницы и используются лабораторией.
4. HTML-fallback разрешён только навигациям. Отсутствующий JS-модуль возвращает сетевую ошибку и не получает HTML вместо JavaScript.

Глобальное кэширование произвольных HTML-ответов не добавлялось. Сохраняются существующие атомарная установка, `skipWaiting`, `clients.claim` и очистка только устаревших кэшей с префиксом приложения.

Исходники `public-web/public/labs/sc5-chronos/`, `public-web/chronos/`, `app/chronos-run.ts` и `app/chronos-panel.tsx` не изменены. Контракты, вычисления, исследовательские ограничения Chronos AI и схемы SC-5 сохранены.

## Воспроизводимый браузерный тест

`tests/e2e/pwa-update.mjs` собирает два закреплённых исторических коммита и текущий рабочий кандидат. Все версии обслуживаются последовательно с одного origin `/Game-GDEYA/`. Исторические сборки используют те же зависимости: lockfile в проверенных версиях совпадает. HTTP-кэш сервера отключён через `Cache-Control: no-store`; настоящие service worker и CacheStorage не подменяются.

Тест проходит восемь контрольных этапов на каждом движке:

1. Устанавливает предшествующий worker через платформу и создаёт SC-5 и досье Студии через интерфейсы.
2. Обновляет его до реально опубликованной ревизии, проверяет побайтную сохранность всех ключей localStorage, воспроизводит отказ холодной и повторной SC-5-навигации без сети и успешное сохранение в уже открытом документе.
3. Моделирует неудачную установку исправления: обязательный `temporal-replay.mjs` отвечает 503. Установка отклоняется; прежний worker и его кэш остаются действующими, журналы не меняются.
4. Повторяет обновление успешно. Проверяет активацию и управление страницей новым worker, удаление устаревших shell-кэшей, сохранность постороннего кэша, localStorage и контрольной записи IndexedDB.
5. Открывает SC-5 без сети по каталогу и `index.html` с новыми параметрами. Проверяет 15 интерактивных вопросов, восстановленную траекторию и ответы модулей с JavaScript MIME из worker. Отсутствующий модуль не получает HTML-fallback.
6. Сохраняет полную оценку без сети, экспортирует и импортирует JSON, закрывает все документы и открывает лабораторию заново. Сравнивает записи; восстанавливает досье Студии. Флаги досье остаются false, `q` и `tensor.Q` — null.
7. Отдельно измеряет холодный запуск основной React-игры: без сети он по-прежнему не поддерживается.
8. В чистом контексте устанавливает кандидат и открывает SC-5 без сети до первого посещения лаборатории. Форма запускается с пустым журналом.

Chromium проверяется одновременно с `context.setOffline(true)` и отключённым origin. У WebKit отдельная проба с минимальным worker, возвращающим буквальный HTML без `fetch`, выявила дефект эмуляции офлайн. Поэтому WebKit проходит приложение при недоступном origin, а результат явно помечается `origin-disconnected-only`. Проба и транспортные ошибки сохраняются в отчёте; это не положительный результат проверки авиарежима.

Такое поведение WebKit описано в [microsoft/playwright #42775](https://github.com/microsoft/playwright/issues/42775). Вывод для этой среды основан также на выполненной независимой пробе, а не только на описании issue.

Команды для полного клона с доступными историческими коммитами:

```bash
npm ci
npx playwright install --with-deps chromium webkit
npm run lint
npm run typecheck
npm test
npm run test:mobile
npm run test:pwa
```

Отчёт создаётся в `outputs/pwa-update/results.json`, в том числе при ошибке внутри сценария. Для отдельного движка используется `E2E_BROWSERS=chromium` или `E2E_BROWSERS=webkit`.

Workflow публикации дополнен обязательным PWA-прогоном в job `mobile`, полным fetch истории для закреплённых сборок и сохранением артефактов. `deploy` уже зависит от `verify` и `mobile`, поэтому падение нового теста блокирует развёртывание. Постпубликационная HTTP-проверка остаётся только проверкой доступности; сама по себе она не считается доказательством офлайн-работы.

## Поддерживаемая граница после исправления

| Сценарий | Подтверждение |
| --- | --- |
| Первое скачивание SHELL и получение обновления | Требуется сеть до успешной активации worker |
| Холодная SC-5, её модули, сохранение/чтение/экспорт/импорт после успешной установки | Chromium: подтверждено при эмуляции офлайн и недоступном origin. WebKit: подтверждено при недоступном origin |
| Сохранность журналов при проверенной цепочке обновлений и закрытии вкладок | Подтверждена; нет миграции или очистки пользовательских хранилищ |
| Неуспешное обновление из-за недоступного обязательного ресурса | Старый worker продолжает работу; новый не считается установленным |
| Холодный запуск главной React-игры и запуск из её `start_url` | Требует сеть; корневой HTML и сборочные assets не входят в текущий SHELL |
| Chronos AI на итоговом экране игры полностью без сети | Отдельно не подтверждён; не объявляется поддержанным |
| Установка через системное «На экран Домой», перезапуск браузера/ОС и физический авиарежим iPhone | Не проверены |
| Сохранность после очистки/вытеснения данных браузером или удаления PWA | Не проверена; lifecycle-тест такого обещания не даёт |

Тест моделирует установку и обновление service worker, но не системную процедуру установки PWA. Регистрация выполняется существующим интерфейсом платформы/Студии. Прямое первое посещение главной игры или SC-5 без предварительной регистрации worker не является подтверждённым способом подготовки офлайн-запуска.

Итог: дефект офлайн-загрузки SC-5 воспроизведён, ограниченное исправление и автоматический шлюз подготовлены. Полноценная офлайн-поддержка всей Game-GDEYA не подтверждена. После одобрения нужны GitHub CI и проверка опубликованных байтов/поведения; до них кандидат не считается опубликованным исправлением.
